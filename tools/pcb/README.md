# PCB chapter generator

This standard-library tool derives Docs 9 and 10 from deliberately cut hardware
snapshots. It never reads routing experiments or edits the source snapshots.
The asset roots `light-v0.1/` and `flex-v0.2/` are stable URL namespaces, **not**
revision claims. JSON, native filenames and download manifests identify revisions.

## Current inputs (8 September 2026)

- Main: `handoff/claude-pcb-learning-cbb8d9fc` in the separate hardware repository.
  LIGHT v0.2, PCB `cbb8d9fc`, 262 features, 241 fitted parts, 71 BOM rows,
  20 schematic sheets.
- Flex: `deliverables/FLEX-mixed-2026-09-08-review` in that repository.
  Upper v0.3 `0af25f8f`; unchanged lower v0.2 `21db9dba` and gimbal v0.2
  `7136c5c3`. There are 292 pads/contacts across the three designs.

Use full hashes from the snapshot verification records, not these short labels.
`build` verifies every MANIFEST.json entry before consuming either snapshot.

## Source contracts

The main handoff contains `viewer-data/board.json`, `bom.json`, `pad-enums.json`
and 17 layer SVGs; `schematic-view/index.json` and sheet SVGs; `downloads/`;
`hardware-current/` native project, BOM, placement and reports;
`fabrication-reference/`; and `public-history/` with portable evidence records.
`engineering-history/` is private input, not a blanket publication source.

The hardware-side `export_viewer_data.py` and `package_handoff.py` in the handoff
are adapted versions of the original exporters. The current packaging adapters
are `scripts/package_learning_refresh.py` and `scripts/finish_learning_snapshots.py`
in the hardware repository. Read them before cutting a later revision; they are
revision-specific, not a promise that arbitrary designs can be substituted.
The current native back-face placement convention differs from the old exporter;
rotation and coordinate checks must remain enabled.

The flex review contains shared verification/electrical/mechanical summaries,
engineering notes and reference templates, plus a directory for each design.
Each directory supplies native project files, connection-table.csv,
design-intent.json, verification.json, ERC/DRC, native geometry, CAM layer SVGs
under view/, and fabrication files. The mixed package was cut with
`scripts/package_flex_learning_refresh.py`, adapting the original
`scripts/check_export_flex.py` workflow. Unchanged designs are copied byte-exact.
The upper native project ZIP includes its custom footprint library.

## Deliberate revision changes

1. Cut and verify the hardware snapshot first. Re-run checks against that exact
   board, or label inherited evidence historical. Never copy old pass counts.
2. Update the main full PCB/ZIP/CSV hashes, SHORT, REVISION and GENERATED in
   build_pcb_assets.py, its revision-specific filenames and teaching entries.
3. Update flex.py DESIGNS if a design directory/version changes. Flex board hashes
   come from verification.json; the directory mapping is still explicit.
4. Update exact revision/census/interface expectations in the tests from the
   independently verified source contract. Do not widen geometric tolerances.
5. Edit chapter prose only outside el-pcb generated marker pairs. Regenerate all
   fourteen blocks; never hand-edit their tables.

## Local loop

Run from this site repository. Set HANDOFF and FLEX to the two snapshot folders
in your own hardware checkout (absolute local paths are not published assets).

```powershell
python tools/pcb/build_pcb_assets.py build --handoff "$HANDOFF" --flex "$FLEX"
python tools/pcb/build_pcb_assets.py render
python tools/pcb/build_pcb_assets.py check
python -m mkdocs build --strict
python -m mkdocs build --strict
.venv/Scripts/python.exe -m pytest tests/e2e -q
```

Use an interpreter with MkDocs for the strict builds, and the site's venv for
pytest. Run `build` twice against frozen inputs and compare every generated byte.
Preview with the `els-site` configuration in `.claude/launch.json`.

## Publication and evidence rules

- Publish only explicit copies in build_pcb_assets.py / flex.py and their download
  manifests: native sources, drawings, derived data, selected evidence, BOM and
  placement files, and deterministic archives. A verified input is not permission
  to publish every file inside it.
- Never publish personal KiCad state, backup directories, fp-info-cache,
  FABRICATION-REVIEW.txt, netlist.xml, vendor identifiers, owner identity or machine
  paths. The scanner checks files and archive members; do not weaken it.
- Never put Markdown under docs/assets. Notes keep their exact bytes as `.txt`.
- `intended`, `cad-checked`, `modelled-current`, `simulated-historical` and
  `measured` describe evidence, not confidence. Neither board has measured data.
  Historical claims link to the byte-exact archived published teaching record,
  containing their bound revision hash; this is not a claim of a new solver run.
- Current full-loop LED electrothermal simulation is not available. The new
  tail/contact resistance screen is narrower. The old A3 upper template is
  explicitly historical; use the current upper 1:1 SVG instead.
- CAM SVGs use a non-native frame. Keep `_frame()` and svgprep's transform
  verification, and the browser copper-bounding-box tests. J100's insertion pads
  belong on B_Cu; all other flex markers retain the F_Cu check. Never relax the
  registration tolerance to accept a visually plausible offset.
- Preserve `docs/assets/pcb/.gitattributes` (`* -text`). After staging, check
  `git ls-files --eol docs/assets/pcb/light-v0.1/kicad/engineered-lighting-rev-a.kicad_pcb`
  reports `attr/-text`, and hash the staged/committed blob, not only the worktree.
- Work on a branch and open a PR against main. CI validates PRs; only a main push
  deploys. Review approval and merging belong to the owner.

The branded successor is cut with `scripts/package_branded_learning.py`. It preserves the original electrical-baseline hashes in evidence, exports current native layer views, and leaves all flex input bytes unchanged.
